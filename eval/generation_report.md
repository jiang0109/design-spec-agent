# 生成层端到端评测报告

**要解决的问题**：此前检索层有 35 题评测，但**生成层只有一个 6 个判定点的示例** ——
"这个 agent 的判定准确率是多少"答不出可信数字。这是整个项目最大的空白。

**结论：端到端准确率 94%（34/36），覆盖率 100%，误报 0、漏报 0、过度自信 0。**

复现：`python -m eval.run_generation_eval`（31 份文档 × 真实 API 调用，约 3.5 分钟）

---

## 一、评测集设计

`eval/generation_set.json`：**31 份文档 / 36 个判定点**，手工编写并标注。

### 期望判定必须由规则推导，不能看输出倒推

每个判定点的 `expect` 都写明推导依据（哪条规则的哪个 param）：

| 判定点 | 期望 | 依据 |
|---|---|---|
| 营销位卡片内边距 20px | fail | SPACING-001 的 `allowed: [12,16,24]`，20 不在其中 |
| 标题字号 20px 行高 26px | fail | TYPO-002 规定行高 = 字号 × 1.5，26/20 = 1.3 |
| 表格单元格行高 1.6 倍 | **pass** | TYPO-002 例外明确"表格单元格不参与行高倍数校验" |
| 纯布局容器未声明 size/variant | **pass** | COMP-001 例外明确"Container / Divider 不声明" |
| 卡片圆角 8px | uncertain | 知识库无任何圆角规则 |

**一条硬规则**：若 agent 结果与 `expect` 不符，按顺序排查 ——
① 匹配逻辑是否命中错点 ② 文档表述是否有歧义 ③ 规则理解是否真的错了。
顺序不能反，否则评测就退化成给模型打掩护。

### 覆盖的三类场景

| 类型 | 点位数 | 检验什么 |
|---|---|---|
| 常规规则（5 类） | 27 | 正常判定能力 |
| **排除型**（excluded） | 3 | 能否识别"规则明确排除该对象 → 不存在违规" |
| **无覆盖**（no_coverage） | 3 | 能否诚实判 uncertain 而不是编造 |

### 四类错误分开统计

它们的危害完全不同，混在一起会掩盖真实问题：

| 错误类型 | 含义 | 危害 |
|---|---|---|
| 误报 FP | 合规判成违规 | 导致返工，消耗团队信任 |
| 漏报 FN | 违规判成合规 | 规范形同虚设，问题流到线上 |
| 过度拒答 | 有依据却判 uncertain | 可用性差，等于没有功能 |
| 过度自信 | 无覆盖却下结论 | **幻觉，最危险** |

## 三、剩余两处错误：都是同一类问题

| 判定点 | 期望 | 实际 | 模型理由 |
|---|---|---|---|
| 主按钮文字色使用 `color-text-primary` | pass | uncertain | "知识库中没有能判定**按钮文字颜色**的规范，检索结果仅涉及背景色令牌" |
| 辅助注释文字 300 字重 | fail | uncertain | "知识库没有覆盖**辅助注释文字字重**的规范，检索内容仅涉及标题字重" |

两处都不是"判定错了"，而是**检索层的相关性闸门把它们拒了**：

- `COLOR-003`（色彩必须用语义 token）对**所有颜色**生效 → 按钮文字色应适用
- `TYPO-003`（字重只用 400/500/600）对**所有文字**生效 → 注释文字应适用

但闸门认为"规则讲的是背景色/标题字重，不是文字色/注释文字字重" → judge 为不适用。

**这是同一个边界第 N 次出现**（回顾）：

| 出现位置 | 现象 | 规模 |
|---|---|---|
| `probe_coverage.py` 覆盖度闸门 | 把"规则范围更宽"判成"无覆盖" | 误拒 7/33 |
| `relevance_report.md` v2 提示词 | 放宽它 → 无覆盖误收 1→2 | 恶化 |
| `e2e_report.md` 端到端 | 表格行高被误拒 | 回归 1 处 |
| **本报告** | **COLOR-003 / TYPO-003 被误拒** | **误拒 2/36** |

**这是当前最主要的剩余缺陷**，且它已经被定位过、被部分修复过（`reject_reason` 解决了排除型，
但没解决"通用规则 + 特定子对象"这一种）。

## 四、过程：这个数字需要 4 轮才稳定

**必须如实记录，否则 94% 会被误读成"一次就做对了"。**

第一次跑出来的结果是 **80%（28/35）**，有 7 处错误。逐处排查后发现：

| 轮次 | 发现的问题 | 性质 |
|---|---|---|
| 1 | G19/G21/G31"未命中"但模型其实判了 | **匹配逻辑缺陷** —— 模型 target 是"布尔属性 loading"/"variant 取值"/"未声明 size 与 variant"，不含我预设的关键词 |
| 1 | G07 误报 | **文档缺陷** —— 我把"字号"和"对比度"混在一句，模型正确拆成两条，关键词命中了错的那条 |
| 2 | G18/G24"未命中" | **匹配逻辑缺陷** —— "属性命名"vs"属性名"、"图层命名"vs"图层名" |
| 2 | G20 漏报 | **标注缺陷** —— 一个判定点涵盖了两条要求（variant 默认值合格、size 缺失），模型正确拆成两条 |
| 3 | G06"未命中" | **匹配逻辑缺陷** —— 模型输出"辅助说明文字**对比度**"，不含"文字色" |
| — | G08/G14 过度拒答 | **真实缺陷**，保留不改 |

### 两次修正从未改动过 `expect`

- 修的是**匹配逻辑**（单关键词 → 关键词列表）与**文档表述歧义**
- 唯一的判定点调整是 G20 **拆分**（一点涵盖两条要求 → 拆成两点），
  文档整体"存在违规"的结论没有变，只是标注粒度对齐了模型+规则的粒度

> **这是本项目第六次「问题出在度量工具而不是被测对象」**：
> Week 1 指标字段名写错 → pilot 选错口径 → 粒度实验浮点阈值判错 →
> 拒答实验三轮改提示词（根因在评测集坏题）→ 结构字段实验结论前提未验证 →
> **本次四轮修匹配逻辑**。
>
> 共同点依旧：错误来源都在"如何度量与解释"这一层。
> 而这次的教训更具体：**统计工具造成的假阴性会低估准确率，
> 并诱导你去"修"一个根本不存在的模型问题。**

## 五、这个 94% 有多可信

### 样本量的限制

36 个判定点、34 个正确 → 比例的标准误 ≈ √(0.944 × 0.056 / 36) ≈ **3.8pp**，
95% 置信区间约 **[87%, 100%]**。

**所以准确讲法应该是"约 94%，95% 置信区间 87%-100%"，而不是"准确率 94%"。**
样本量是当前最主要的可信度限制。

### 其它限制

- **单次运行**：相关性判定存在运行间波动（`relevance_report.md` 已记录，
  边界题分数会翻转），本次未做多次重复。
- **评测集由我编写**：虽然期望值都从规则 params 推导，但选哪些规则、怎么表述，
  仍受我的理解影响。真实规范库的边界情况更杂。
- **文档篇幅极短**：每份只有 1-2 句，没有测试长文档的分段/截断行为。
- **一个判定点可能被模型拆成多条**（见"多余判定"，本次 5 条）：
  不计入准确率，但实际使用时会让报告变啰嗦。

## 六、结论与下一步

### 当前能力画像

```
排除型识别（规则明确排除该对象）  : 3/3   100%
无覆盖识别（诚实判 uncertain）    : 3/3   100%
常规规则判定                      : 28/30 93%
误报 / 漏报 / 幻觉                : 0 / 0 / 0
```

**核心主张"agent 能说'我不知道'"现在有了可信数字支撑。**

### 下一步优先级

| 优先级 | 动作 | 理由 |
|---|---|---|
| **1** | **修「通用规则 + 特定子对象」的误拒** | 唯一剩余的错误类型（2/36），且已知是同一边界 |
| 2 | 扩充到 100+ 判定点 | 当前 CI 宽达 ±7pp，无法支撑"准确率 94%"这种表述 |
| 3 | 多次重复运行，量化波动 | 单次运行的结论不够稳 |
| 4 | 加长文档用例 | 覆盖分段/截断行为 |

### 对"优先级 1"的具体建议

两次误拒的共同结构是：**规则是通用的（"所有颜色"/"所有文字"），
问题问的是它的一个特定子对象（"按钮文字色"/"注释文字字重"）**。

`reject_reason` 的 `excluded / not_applicable / no_coverage` 三值**没有覆盖这种情况** ——
它不是"不适用"，而是"适用"，只是表述粒度不同。

可行的方向（需要单独实验验证，不要直接改）：
- 在拒绝原因里增加第四种：`general_rule_applies`（通用规则可适用，需降级为 relevance=2）
- 或在相关性判定里显式提供规则的**适用范围描述**（如果规范能提供 `scope` 字段）
- 注意：`relevance_report.md` 的 v2 实验已证明"放宽措辞"会让无覆盖误收上升 ——
  所以这条修复必须同时看**误收与误拒两个方向**，不能只盯一个指标。
